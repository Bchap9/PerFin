# Build prompt

Paste the block below into a new Claude Code session on this repository. It is
resumable: the same text works for the first session and every later one,
because progress is tracked in ROADMAP.md checkboxes and CHANGELOG.md.

---

Build PerFin to v1.0.0 from the design in this repository. Use workflows and
subagents (ultracode) to parallelise independent work. Treat the docs as the
spec and the roadmap as the plan.

## Read first, in this order
1. README.md, docs/VISION.md
2. docs/ARCHITECTURE.md, docs/REPO_STRUCTURE.md, every file in docs/adr/
3. docs/DATA_MODEL.md, docs/API.md, docs/AUTH.md, docs/INGESTION.md,
   docs/AI_ACCESS.md
4. docs/SECURITY.md (every row is a requirement, not a suggestion)
5. docs/ROADMAP.md and CHANGELOG.md (if it exists) to find where to resume

## Decisions already made (do not ask, do not revisit)
- Licence: AGPL-3.0. Add LICENSE and SPDX headers in Phase 0.
- Base currency default USD; multi-currency per DATA_MODEL.md.
- Tax forms: US set (W-2, 1099 family, 1098, 1095) first, implemented as a

- Authentik may run on a private LAN address; honour
  PERFIN_OIDC_ALLOW_PRIVATE_ISSUER exactly as documented.
- No language-model client of any kind in the codebase (ADR-0007). If you
  think one would help, write it down in docs/ROADMAP.md "parking lot" and

- Stack per ADR-0001: Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic + uv;
  React 18 + TypeScript + Vite + TanStack Query/Router; PostgreSQL 16;
  Postgres-backed queue (ADR-0002); libsodium envelope encryption
  (ADR-0003); server-side sessions (ADR-0005); sandboxed extraction
  (ADR-0006).

## How to work
- Work on the branch this session was given. Never push elsewhere.
- Go phase by phase in ROADMAP.md order. Within a phase, fan out independent
  items to parallel agents (for example: backend domain package, its API
  router, its frontend feature, its tests) and reserve one agent for security
  review of the phase before it is marked done.
- A phase is done only when every checkbox in it is ticked in ROADMAP.md,
  tests pass, lint and strict type checks pass, and the security review agent
  has signed off against docs/SECURITY.md. Then: update CHANGELOG.md, commit
  with a message naming the phase, push, and continue to the next phase.
- Commit at least once per completed roadmap item, not only per phase, so a
  session that ends mid-phase loses little. Push after every commit.
- If context is running low or the session must end, make sure ROADMAP.md
  checkboxes and CHANGELOG.md reflect reality, commit and push, and write a
  short "Resume here" section at the top of CHANGELOG.md describing what is
  in progress and what to do next. The next session starts from that.
- Never mark a checkbox for work that is stubbed, skipped or untested. Never
  disable, skip or weaken a test to get green. Report what could not be
  verified in this environment and why.
- Keep docs in sync: when the implementation diverges from a doc for a good
  reason, change the doc in the same commit and add an ADR if the decision is
  structural.

## Non-negotiable engineering rules
- Every row in docs/SECURITY.md and the M-rows in docs/AI_ACCESS.md must map
  to code and to a test. Keep a `docs/security/CONTROLS.md` table that maps
  each row id to the file(s) and test(s) that implement it; update it as you
  go. A phase's security review checks this table.
- The ai:read serialisers are allowlists. A CI test must enumerate every
  SQLAlchemy column and fail if any is not classified as exposed or denied for
  AI access. The free-text scrubber must have a corpus test with zero leaks.
- The API process never opens file content beyond magic-byte sniffing and
  hashing. All extraction runs in the worker, in a subprocess with rlimits,
  timeouts, seccomp and no network.
- `perfin config check` refuses to start with insecure settings outside
  PERFIN_DEV_MODE. Containers run non-root, read-only, cap_drop ALL.
- No real financial documents anywhere in the repo. Test fixtures are
  synthetic and generated by scripts you write.
- mypy --strict on the backend and tsc --strict on the frontend, Ruff,
  Bandit, ESLint with security rules, pip-audit and npm audit all run in CI
  and must pass.
- Conventional, descriptive commit messages. No model names in commits.

## Deliverables for v1.0.0 (beyond the roadmap checkboxes)

  host with Docker Compose: prerequisites, generating secrets, the master key

  proxy with Caddy (plus Traefik and nginx snippets), enabling the drop

  hardening checklist from docs/SECURITY.md as a walk-through.

  Ollama-backed MCP host, with the exposure preview walkthrough.
- docs/BACKUP_RESTORE.md plus scripts/backup.sh and scripts/restore.sh with
  a restore verification test.
- docs/UPGRADING.md and a CHANGELOG.md in Keep a Changelog format.
- A GitHub Actions release workflow that builds the multi-arch image, runs
  Trivy, generates an SBOM, signs with cosign and publishes on a v* tag.
- A `make dev` / scripts/dev.sh that brings up a local dev stack with seeded
  synthetic data.
- A short docs/OPERATIONS.md: logs, metrics, health endpoints, common
  failure modes and their fixes.

## Verification before calling it 1.0.0
- Bring the Compose stack up (if Docker is available in your environment;
  otherwise say so and run the integration suite against a local Postgres),
  complete the admin bootstrap, log in locally with MFA, upload a synthetic

- Do not create a pull request or a tag. Push the branch and stop with a
